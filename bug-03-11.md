# Relatório de Bug: A Corrida dos Tiles (03/11/2025)

Este documento detalha a investigação sobre o bug intermitente que causa o desaparecimento de tiles durante a geração em tempo real, resultando em uma contagem incompleta de tiles na interface.

## 1. Resumo Executivo

O sistema está sofrendo de uma _race condition_ (condição de corrida) clássica do React, conhecida como "stale state" (estado obsoleto). O hook `useCompanyManager` está, sob certas condições de timing, substituindo o estado atualizado dos tiles (recebidos via SSE) por uma versão mais antiga (obsoleta) do estado, causando a perda de tiles na interface. A arquitetura de dados e eventos (Fluxo 2.0) está correta, mas a implementação da atualização de estado no frontend é falha. A correção envolve uma mudança pontual para garantir que o hook sempre acesse a versão mais recente do estado ao realizar atualizações.

---

## 2. Sintomas Observados

- **Renderização Parcial:** Apenas uma parte dos tiles (ex: 4 de 8) substitui os placeholders, enquanto o restante permanece em estado de "gerando".
- **Contagem Inconsistente:** O número total de tiles visíveis (placeholders + renderizados) às vezes diminui (ex: cai para 6), indicando que elementos estão sendo removidos do DOM.
- **Perda de Progresso no Refresh (F5):** Após um refresh, todos os tiles voltam a ser placeholders, indicando que eles não foram salvos corretamente no banco de dados. Este sintoma foi causado por um bug de validação secundário (`"tile.status" is not allowed`), agora corrigido. O foco deste relatório é a falha na renderização em tempo real.

## 4. O Fluxo de Dados: Da Geração à Tela

Para entender o bug, é crucial entender o fluxo de dados em paralelo que acontece quando a página `/admin` carrega com um `job_id`:

**Fluxo A: A Chegada dos Tiles (Rápido)**
`SSE Backend` -> `useSSEManager` -> `AdminDashboardContainer` -> `setSelectedCompany` -> **(Atualiza os tiles no estado)**

1.  O `useSSEManager` estabelece a conexão.
2.  O backend envia um evento `job:result-completed` com um novo tile.
3.  O listener no `AdminDashboardContainer` é acionado.
4.  Ele chama `setSelectedCompany`, pedindo ao `useCompanyManager` para adicionar o novo tile à "empresa temporária" que está em memória.

**Fluxo B: O Carregamento do Workspace (Lento)**
`Browser` -> `useWorkspace.loadGuestWorkspace` -> `API /api/guest/workspace` -> `DB` -> **(Retorna os dados do workspace)**

1.  O `useWorkspace` faz uma chamada à API para buscar os dados do workspace (que, no início, não tem tiles).
2.  A API busca no banco de dados e retorna a estrutura do workspace, incluindo a `company` "Upwork" com seu array de `tiles` vazio.

**O Ponto de Colisão:** O `useEffect` principal do `useCompanyManager` observa a chegada dos dados do **Fluxo B** e decide que é hora de trocar a "empresa temporária" (do Fluxo A) pela "empresa real" que acabou de chegar. É nesta troca que o bug acontece.

---

## 5. Diagnóstico: A Causa Raiz - Stale State (Estado Obsoleto)

O `useEffect` no `useCompanyManager` tem uma dependência no `workspace`. Quando o `workspace` (Fluxo B) finalmente carrega, o `useEffect` é executado. O código dentro dele faz o seguinte:

1.  "Vejo que o `workspace` chegou."
2.  "Encontro a empresa 'Upwork' dentro dele."
3.  "Vou substituir a `selectedCompany` atual (a temporária) por esta nova que veio do workspace."
4.  **O ERRO:** Ao criar a nova versão da `selectedCompany`, ele acidentalmente usa uma "foto" antiga (um _stale state_) da `selectedCompany` temporária, de **antes** dos tiles do SSE (Fluxo A) terem sido adicionados a ela.

**Ilustração do Bug:**

```
TEMPO 0ms:
- selectedCompany = { name: 'temp', tiles: [] }
- workspace = null

TEMPO 500ms (SSE Rápido):
- Chega o Tile 1.
- O estado é atualizado.
- selectedCompany = { name: 'temp', tiles: [Tile 1] }

TEMPO 600ms (SSE Rápido):
- Chega o Tile 2.
- O estado é atualizado.
- selectedCompany = { name: 'temp', tiles: [Tile 1, Tile 2] }

TEMPO 1000ms (Workspace Lento):
- `workspace` finalmente carrega do DB.
- O `useEffect` do useCompanyManager é acionado.
- Ele olha para uma "foto" do `selectedCompany` tirada em TEMPO 0ms.
- LÓGICA COM BUG: "Vou criar a nova company real. Pego a company do workspace e adiciono os tiles da company temporária... (olhando a foto de 0ms)... ah, ela tem 0 tiles."
- O estado é substituído.
- selectedCompany = { name: 'Upwork', tiles: [] } // <-- OS TILES 1 E 2 FORAM APAGADOS!

TEMPO 1100ms (SSE Rápido):
- Chega o Tile 3.
- O estado é atualizado.
- selectedCompany = { name: 'Upwork', tiles: [Tile 3] }
```

Isso explica perfeitamente por que você vê alguns tiles, depois eles somem, e depois outros aparecem. Os que chegam _durante_ o carregamento do workspace são perdidos.

---

## 6. Plano de Correção Cirúrgico

A solução é garantir que, no momento da atualização, o React sempre use a versão mais fresca e atualizada do estado, em vez de uma "foto" antiga. Isso é feito usando a forma funcional do `setSelectedCompany`.

- **Arquivo a ser modificado:** `dashboard/hooks/useCompanyManager.js`

- **Lógica a ser alterada:** Em vez de ler diretamente a variável `selectedCompany` (que pode estar obsoleta) dentro do `useEffect`, passaremos uma função para `setSelectedCompany`. Essa função nos dará acesso garantido ao estado mais recente (`prevCompany`).

**Código Atual (Com Bug):**

```javascript
// ... dentro do useEffect ...
setSelectedCompany({
  ...companyFromWorkspace,
  tiles: selectedCompany?.tiles || [], // USA A "FOTO" ANTIGA DE selectedCompany
});
```

**Código Corrigido (Proposto):**

```javascript
// ... dentro do useEffect ...
setSelectedCompany((prevCompany) => ({
  ...companyFromWorkspace,
  tiles: prevCompany?.tiles || [], // USA O ESTADO MAIS RECENTE (prevCompany)
}));
```

Esta mudança de uma linha garante que a "troca de turno" seja atômica e segura, preservando todos os tiles que chegaram via SSE e resolvendo a _race condition_ de uma vez por todas.
